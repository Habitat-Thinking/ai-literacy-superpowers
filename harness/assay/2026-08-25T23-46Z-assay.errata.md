# Errata — 2026-08-25T23-46Z-assay.md

Corrections to findings in this assay. The assay itself is append-only and is never edited; this file is the channel.

One section per corrected finding. A later correction to the same finding is appended, never substituted.

## finding-1

**The finding does not proceed, and its proposed rule is not built.** Adjudicated
2026-08-25 against `docs/superpowers/objections/harness-gc-rule-outside-loop.md`
— twelve objections, four accepted, eight moot.

Four corrections, in descending order of consequence.

**The stated harm is false.** The finding claims "a reader asking when the
project stopped checking template currency finds the answer only by knowing
which spec to open". Git history answers it in one command:
`git log -S "### Template currency" -- HARNESS.md` returns both endpoints —
`f316d94` where the rule entered, `2fce5a4` where it left — with the author,
the date, the PR, the issue and the full reasoning in the commit body. That is
more than a decision record would carry, at no cost to the governing document.
Since the harm is not real, there is nothing for the proposed rule to prevent.

**The corroboration does not clear the two-assay threshold.** Both cited
pre-registrations name a rule *appearing* without a record — assay 2's
finding-3, "if a third assay observes a constraint **appearing** without a
record"; assay 3's finding-4, "a fourth assay that observes a **hand-added**
constraint". The observed event was a removal, and
`check-harness-decisions.py:914-918` exempts retirements from the threshold
deliberately: "The threshold exists to make rules hard to ADD; applying it to
removal would mean a rule that turned out to be wrong needed two assays'
evidence before anyone could withdraw it — the exact inversion of 'hard to add,
easy to retire'." Read on the pre-registrations' own terms the finding has one
observation of the harm, not three.

**"The loop cannot express this change" is a proxy claim the finding's own rule
disproves.** It rests on counting a phrase across eight files; forty lines later
the proposed rule supplies the workaround — `harness-loop` routes to
`HARNESS.md` (`surfaces.yaml:23`), so a record naming the GC rule in prose was
available throughout. The honest statement is weaker: the loop routes to the
file with no section granularity, and nobody used the awkward path. That is a
discipline gap, not a schema gap.

**The proposed rule instructs something the tooling refuses.** It says to use
"`harness-loop` with an explicit `target: HARNESS.md`".
`harness-registrar.py:777-781` calls `die()` when `--target` is supplied for a
routed classification, and `harness-loop` is routed. The finding's own metadata
block declares no `target` — the field its rule mandates — while finding-2's
block in the same assay does.

**What stands.** The heading-diff observation itself is sound and was verified
independently: `HARNESS.md` went 64 `### ` headings to 63 between `9a160d6` and
`9995863`, with exactly `Template currency` removed and nothing added, and
`harness-registrar.py check` returned `OK (6 decision(s))` afterwards. A rule
left the governing document and no mechanism remarked on it. That observation is
not corrected here; what is corrected is the harm it was said to cause and the
rule proposed to prevent it.

The underlying question — whether the loop should have a governed path for
retiring a GC rule — remains open as **#606**, and a reader of that issue should
read this errata before citing finding-1 as its evidence base.

**Two observations from the objection record that outlive this finding**, both
recorded as moot there rather than acted on, and neither carrying evidence of its
own yet:

- The two-assay threshold is distinct by assay *file*, so a `no-change` finding
  that pre-registers a condition functions as a corroboration token
  (`check-harness-decisions.py:904-907`). Whether the threshold should mean two
  independent observations of the harm is an open question for the approver at a
  future gate.
- Extending the existing deterministic, git-backed *Harness governance is applied
  and undrifted* check is a better shape than adding an advisory rule with no
  dispatch path — though the git-history point above weakens the case for
  building anything here.
